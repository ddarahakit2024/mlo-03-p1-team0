# MOA Parts UI 컴포넌트

여러 화면이 같이 쓰는 표시용 컴포넌트다. API 를 부르지 않고 props 로 받아 그리며, 사용자의 행동은 emit 으로 알린다.
색은 `:root` 토큰(`--brand` 등), 버튼·재고 표시는 `src/assets/shop.css` 의 `shop-` 클래스를 쓴다.

예:

    import { ProductGrid, ProductSearchBar, SiteLayout } from '../components/index.js'

    <SiteLayout active-page="products">
      <ProductSearchBar v-model:keyword="search" @search="runSearch" />
      <ProductGrid :products="products" label="그래픽카드 상품 목록" />
    </SiteLayout>

- SiteLayout activePage: 주요 메뉴는 "상품"(products, /products), "가격 추적"(alerts, /my?tab=alerts), "커뮤니티"(community, /community/*·/questions/*) 세 개다. questions(질문 게시판 화면이 넘기는 값)는 community 와 같이 "커뮤니티"를 강조한다. compare 는 헤더 비교 아이콘·하단 탭 "비교", cart 는 장바구니 아이콘·하단 탭·프로필 메뉴 "장바구니", orders 는 프로필 메뉴 "주문 내역", my·alerts(마이페이지가 탭에 따라 넘긴다)는 프로필 메뉴 "마이페이지"와 하단 탭 "마이"를 aria-current="page" 로 강조한다. auth(로그인 화면)는 하단 탭 "마이"만. 관리자 화면(/admin/returns·/admin/recommendations)은 spec 대로 빈 값('')을 넘긴다(아무것도 강조하지 않는다).
- SiteLayout 프로필 드롭다운: 위에서부터 이름, "마이페이지"(/my), "장바구니", "주문 내역", 그리고 GET /user/me 의 role 이 "admin" 이면 "반품 관리"(/admin/returns, spec docs/specs/2026-11-01-returns-refunds.md)와 그 아래 "추천 학습"(/admin/recommendations, spec docs/specs/2026-11-03-product-recommendations.md), 마지막에 로그아웃. 시뮬레이터는 "장바구니"·"주문 내역"을 이름(exact)으로 찾으므로 두 링크의 이름은 바꾸지 않는다.
- SiteLayout 은 API 를 직접 부르지 않는다. 로그인한 이름은 공용 로그인 상태(src/stores/authSession.js)를, 배지 숫자·토스트는 헤더 공용 상태(src/stores/siteStatus.js: 회원이면 GET /cart·GET /notifications/unread-count 를 한 번, 화면이 setter·showToast 로 바꾼다)를 `subscribe` 해서 보여 준다. 헤더(디자인): 로고(/images/logo.png 40px)+"MOA Parts"(1024px 아래 숨김), 주요 메뉴, 가운데 검색(GET /products, name search, 숨은 search_action), 비교(/compare)·장바구니(/cart) 아이콘(주황 배지, 이름에 숫자 "장바구니, 3개 담김"), 알림(/my?tab=notifications, 읽지 않은 알림이 있으면 빨간 점 + 이름 "알림, 읽지 않은 알림 N개"), 비회원은 "로그인" 링크, 회원은 이름 첫 글자 동그라미 프로필 버튼(`aria-expanded`·`aria-controls`, 숨김 글자 "<이름> 계정 메뉴"). 버튼은 마우스를 올리거나·누르거나·키보드로 포커스하면 드롭다운을 연다. 마우스가 벗어나면 잠시 뒤, Esc(버튼으로 포커스)·바깥 누르기·Tab 으로 나가면 닫는다. 로그아웃 버튼은 `authSession.logout()`(POST /user/logout 뒤 로그인 상태를 다시 부른다)을 쓴다. 로그아웃에 성공하면 `logout` 이벤트를 남기고 `/` 로 이동하고(stores 의 goToMain), 실패하면 헤더 아래에 role="alert" 안내를 보여 준다. 760px 아래에서는 주요 메뉴·비교·장바구니 아이콘을 숨기고 화면 아래에 고정된 하단 탭 막대(`<nav aria-label="하단 메뉴">`: 상품·커뮤니티·비교(배지)·장바구니(배지)·마이(/my, 비회원은 /login))를 그리며 그만큼 아래를 비운다. 바닥글은 로고·MOA Parts·"내 PC에 맞는 부품을 가장 좋은 가격에"·© 올해. 토스트는 아래 가운데 알약(role="status"·aria-live="polite" 영역은 늘 있고 문구만 바뀐다)이고 떠 있는 비교 트레이·하단 탭 위로 올라간다.
- InlineConfirm 은 브라우저 confirm 대신 쓰는 화면 안 확인 상자다(질문·답변·리뷰 삭제). 열리면 "아니요"에 초점을 두고, 진행 중(busy)에는 두 버튼을 막고 "예" 자리에 busyLabel 을 보여 준다. 쓰는 화면이 삭제 진행·실패 문구를 맡는다.
- ProductGrid 의 카드(ProductCard)는 링크 하나라서 버튼은 카드 링크 밖(li 안, 카드 뒤)에 둔다. li 가 카드 테두리다. 비교 버튼은 `<button aria-pressed>`("+ 비교"/"비교 중")이고 사진 오른쪽 위에 겹쳐 보인다. 접근 가능한 이름은 "<상품 이름> 비교함에 담기"/"<상품 이름> 비교함에서 빼기". 링크 아래 줄에 타몰 비교 문구(storeLine: MOA 최저 초록, 다른 곳이 더 쌈 노랑)와 "담기" 버튼(이름 "<상품 이름> 장바구니에 담기", 담는 중 "담는 중..."·비활성, 품절이면 "품절"·비활성)이 있다. 버튼을 링크 안이나 카드 앞에 두지 않는다. 비교·담기 버튼은 select(클릭 이벤트)를 알리지 않는다. 데스크톱은 `repeat(auto-fill, minmax(230px, 1fr))`, 560px 이하는 2열.
- ProductDropList 는 첫 화면의 "30일 하락폭 큰 부품" 가로 줄이다(h2 + 기준 "30일 전 가격 기준", 로딩 "하락한 부품을 불러오는 중입니다..." role="status", 오류 role="alert" + "다시 시도" → retry, empty 면 아무것도 그리지 않는다). 카드는 링크 하나(작은 사진·변동률 배지(PriceChangeBadge, 접두 없음)·이름 h3 두 줄·30일 추세선·가격·1년 최저가 문구)이고 220px 카드가 자기 영역 안에서만 가로로 넘어간다(scroll-snap). 화면이 `id="drops"` 를 넘겨 소개의 "하락 중인 부품 보기"(#drops)가 이 영역으로 이동한다. 목록 이름은 h2 와 같다(" 목록"으로 끝나지 않는다).
- ProductCompareBar 는 비교함 막대다(spec docs/specs/2026-11-01-event-enrichment.md). 디자인의 비교 트레이: floating(기본)이면 화면 아래 가운데에 떠 있고(760px 아래에서는 하단 탭 막대 위, 좁은 화면에서는 이름을 숨기고 사진만), SiteLayout 이 그만큼 페이지 아래를 비워 바닥글을 가리지 않는다. floating=false 면 페이지 끝 제자리. 비교함이 비면 아무것도 그리지 않는다. 제목 h2 "비교 n/4"(+ 카테고리), 담은 상품(작은 사진·이름·빼기 버튼 "<이름> 비교함에서 빼기"), "비교하기" 링크(/compare, showLink=false 면 숨김), × 비우기(숨김 글자 "비교함 비우기"), 안내 줄(role="status", 늘 있고 비어 있으면 높이 0)과 다른 카테고리 안내일 때 "비교함 비우고 담기". 목록 이름은 "비교함에 담은 상품"(시뮬레이터가 상품 목록을 " 목록"으로 끝나는 이름으로 찾으므로 그렇게 끝나지 않게 한다). 비교함 상태·규칙·저장은 src/stores/compareViewModel.js 의 createCompareBox 가 맡고 화면이 넘긴다(헤더 배지는 화면이 siteStatus.setCompareCount 로 맞춘다).
- ProductRecommendations 는 상품 상세의 "함께 보는 부품" 영역(추천, spec docs/specs/2026-11-03-product-recommendations.md)이다. `<section>` + h2 "함께 보는 부품", 상태 문구는 spec 상태표 그대로(로딩 "추천 상품을 불러오는 중입니다..." role="status", 빈 목록 "추천할 상품이 아직 없습니다.", 오류는 받은 error(없으면 "추천 상품을 불러오지 못했습니다. 다시 시도해 주세요.") role="alert" + "다시 시도" → retry). 카드는 링크 하나(작은 사진·30일 변동 배지(PriceChangeBadge, 접두 없음)·이름 h3 두 줄·근거 글자 "함께 본 상품"/"비슷한 가격대"·가격·30일 추세선(aria-hidden, 변동은 배지 글자로), /products/{id})이고 목록은 `ul aria-label="추천 상품"`. 시뮬레이터가 상세 화면의 첫 h1·모든 dt 를 읽으므로 h1·dl/dt 를 쓰지 않고, 목록 이름이 " 목록"으로 끝나지 않게 한다. `repeat(auto-fill, minmax(180px, 1fr))`, 640px 이하 2열. 노출·클릭은 화면이 createImpressionTracker(list 'recommendation')로 재고 observeItem·select 로 잇는다.
- ProductRating 은 "★ 4.5 (12)" 를 role="img" + aria-label("평점 5점 만점에 4.5점, 리뷰 12개")로 그린다. 평균은 서버 값을 소수 1자리로 보여 주기만 한다.
- ProductPurchaseCard 는 상세 가격 카드의 구매 영역(`section aria-label="구매하기"`, 가격은 ProductPriceSummary)이다. 재고 표시·수량 선택(1~min(10, 재고)) 아래 버튼 줄에 "장바구니 담기"(주황, 넓게)·"바로 구매". 재고가 0 이면 "품절"과 안내를 보여 주고 두 버튼을 비활성화한다. 비교함·목표가 알림 버튼은 구매 영역 밖이라 화면이 이 카드 옆(넓으면 같은 줄로 보이게)에 둔다.
- ProductPriceSummary·ProductPriceChart 는 상품 상세의 가격 카드 윗부분과 "가격 추이" 그래프다. 표시 값은 src/stores/productDetailViewModel.js(priceTiles·storeSummary)와 src/stores/priceHistoryViewModel.js(dailyStorePrices·priceTrendChart·chartIndexAt·stepChartIndex)가 만든다. 그래프는 viewBox 640×240, 가로선 4개("N만"), 1년 최저가 점선(초록), 주황 선 + 그라데이션, 마지막 점, x 축 날짜 4개이고, 표로 보기(판매처별 표)는 화면이 `<details>` 로 둔다.
- ProductQuantitySelect 는 재고가 줄어 지금 수량이 max 보다 커도 지금 수량을 보여 준다(max 보다 큰 값은 고를 수 없다).
- CommunityShell 은 커뮤니티의 모든 화면(/community, /community/*, /questions/*)을 감싸는 2단 레이아웃이다(SiteLayout 안에 둔다, 디자인 MOA Parts "COMMUNITY SHELL"). 왼쪽 240px sticky `<aside>` 의 `<nav aria-label="커뮤니티 게시판">` 링크 이름은 정확히 "커뮤니티 홈"·"질문 게시판"·"자유 게시판"·"견적 게시판"(시뮬레이터가 이 이름으로 찾는다. 글 수는 aria-hidden)이고 지금 게시판에 aria-current="page"(주황 바탕 + 왼쪽 막대). 그 아래 "바로 쓰기": 질문하기 /questions/new, 견적 요청하기 /community/build/new(강조). 760px 이하는 본문 위의 가로 알약 목록(목록 안에서만 가로로 넘긴다) + "+ 견적 요청" 링크. 본문 칸은 컨테이너(cm-main)라서 community.css 가 본문 폭(@container)으로 목록·폼 모양을 바꾼다.
- CommunityPartsTable 은 견적 답글의 부품 줄(디자인 "받은 견적" 카드: 사진·상품 이름 링크·"브랜드 · 카테고리 · N개"·줄 금액, 2개 이상이면 개당 판매가, 줄에 change_30d_pct(또는 price_trend.change_30d_pct)가 있으면 PriceChangeBadge)을 `<ul aria-label="{caption} N줄">` 로 그린다. 금액은 서버 값(price_krw, line_total_krw, items_total_krw)을 그대로 보여 주고, 재고가 0 이면 "품절". 사진이 깨지면 `/product-placeholder.svg`. 견적 카드처럼 위에 합계를 크게 보여 주거나 여러 개를 한 화면에 둘 때는 showTotal=false·showNote=false.
- CommunityPartsPicker 는 카테고리 → 상품 → 수량 → 추가, 줄 빼기, "예상 합계"(상품 목록 가격 × 수량, 화면 표시용)를 그린다. API 를 부르지 않는다: 카테고리를 고르면 request-products 를 알리고 화면이 GET /products 결과를 catalog 로 넘긴다. 최대 15줄, 수량 1~10, 같은 상품 두 줄 금지(src/stores/communityViewModel.js 의 addPartLine). 한 화면에 여러 개를 둘 수 있게 입력 id 는 idPrefix 로 만든다. budgetKrw 를 넘기면 "예산 ○○과 비교" 배지(예산 안 · N원 남음 / 예산에 딱 맞음 / 예산 초과 · N원, budgetGapBadge)를 보여 준다. 이것도 화면 표시용이다.
- CompatibilityPanel 은 부품 호환성 결과(spec docs/specs/2026-11-01-compatibility-rules.md)를 보여 준다. API 를 부르지 않는다: 화면이 POST /compatibility/check 를 부르고 result·state 를 넘긴다(늦게 온 이전 응답은 화면이 버린다). 상태 문구는 spec 상태표 그대로(확인 중 "부품 호환성을 확인하는 중입니다..." role="status", 문제 없음 "함께 쓸 수 있는 부품입니다.", 주의 "주의할 점 N개", 호환 안 됨 "함께 쓸 수 없는 부품이 있습니다(N개)", 오류 "호환성을 확인하지 못했습니다. 다시 시도해 주세요." role="alert" + "다시 시도" → retry). 문제 목록은 수준 배지 글자(호환 안 됨·주의·안내)와 서버 문구, 균형은 -2~2 SVG 막대(role="img" + aria-label, 같은 내용의 글자 "CPU ↔ 그래픽카드 균형 균형 좋음 점수 0.42"), 전력은 "예상 소비 전력 520W / 파워 850W"(파워가 없으면 "파워 없음"). context 가 cart 면 제목 h2, quote_compose 면 h3(견적 보내기 h2 아래)인 `<section>` 이고, quote_card 면 상자 없는 호환성 한 줄(아이콘 글자 ✓ ! ✕ + "부품 호환성 · 문구", 상태 색)과 "호환성 자세히 보기" 버튼(aria-expanded·aria-controls)으로 펼치는 `<div>` 다. 버튼 이름은 장바구니의 기존 이름(주문하기·삭제·수량)과 겹치지 않는다. 계산(상태 문구·배지·좌표·전력 문구)은 src/stores/compatibilityViewModel.js.
